## Per issue

### #112 — `--yolo` via watch/loop
`squad watch` and `squad loop` now run with `--agent-cmd /usr/local/lib/squad-on-aca/squad-agent`.
The wrapper (`worker/squad-agent`, shipped in the image, root-owned and non-writable) execs
`copilot -p <prompt>` plus the resolved policy argv, and adds `--additional-mcp-config @<repo>/.mcp.json`
when `.mcp.json` exists — **without** `--yolo`. It fails closed (exit 78) if the policy cannot be resolved.
The policy is transported through the environment as a JSON array produced by `agent-policy.js`, so the
wrapper never re-resolves it differently. We deliberately do **not** rely on the Squad 0.13 `{prompt}`
token, because both 0.11 and 0.13 append `-p <prompt>` to a custom agent command.

**Parity decision (as briefed):** watch/loop keep today's *effective* deny set (the `squadFlags` subset).
Multi-word deny rules are announced as NOT enforced on this path, so watch agents can still push and open
PRs. `SQUAD_WATCH_STRICT_POLICY=true` is the opt-in that uses the full argv.

Tests: `test_squad_agent_wrapper.sh` (91/0) proves the spawned argv never contains
`--yolo`/`--allow-all`/`--allow-all-paths`/`--allow-all-urls`, does contain the MCP config when
`.mcp.json` exists, honours the strict opt-in, and fails closed.
Dockerfile `COPY`/`sed`/`chmod`, `scripts/validate.ps1` and `test_image_layout.sh` expectations updated.

**Open:** a follow-up note for #112 is in `.squad/decisions/inbox/112-watch-strict-policy-followup.md`
(making strict the default once multi-word rules are enforceable on this path).

### #113 — governance locks vs Squad 0.13 runtime state
Three classes, defined once in `worker/lib/agent-policy.js` and consumed by `worker/lib/squad-policy.sh`
and `scripts/validate.ps1`:

- **locked** — `charter.md` and everything else previously locked, plus all of `.squad/identity/` except `now.md`.
- **append-only** — `.squad/memory/audit.jsonl`. Rotation is made impossible mid-session and a truncation to
  *exactly* the baseline length is treated as a violation, via a high-water mark.
- **reported-mutable** (new) — `.squad/casting/policy.json`, `registry.json`, `history.json`, and
  `.squad/identity/now.md`. Hashed at baseline; changes are allowed but listed in the governance report and
  appended to the PR body. Change-then-revert is still reported.

`.squad/identity/` reasoning: `now.md` is the team's "current focus" scratchpad and Squad 0.13 writes it
during normal operation, so locking it would break the runtime; everything else under `identity/` is
durable self-definition and stays locked.

`validate.ps1` section 7 now asserts the new classes precisely instead of asserting
`memory/audit.jsonl` is locked. Behavioural tests live in `test_governance_guard.sh` (148 assertions,
real repo, real hardening, real writes).

### #115 — signal handling
`worker/lib/squad-signal-forwarding.sh` runs the `squad watch`/`squad loop` child in the background,
traps TERM/INT, forwards them, and `wait`s again so the true child exit code is recovered rather than the
synthetic `128+signo`. The existing EXIT trap and `squad_policy_checkpoint` behaviour are preserved.
`deploy.ps1` sets a termination grace period for `ca-squad-aca-watch` using
`--termination-grace-period` (verified present on both `containerapp create` and `update` in the Azure CLI
source — not guessed). Process-level test with a stub `squad`: `test_signal_forwarding.sh` (19/0).

**Not done, with evidence:** wiring `squad-aca watch stop` to Squad 0.13 `--sentinel-file`. The flag is
undocumented upstream and *inverted* — watch creates the file at startup and stops when it is **removed**.
Triggering that needs an exec channel into the running replica, which the CLI surface does not have.
Documented as a limitation.

### #116 — `squad health --json` gate
Runs after bootstrap and before hardening in every mode that runs an agent. Fails closed (exit 78) on
`status: "fail"`, logging the failing check ids. A "Squad health" row was added to `squad-aca doctor`.
On a CLI older than 0.13 it reports **unavailable** and does not pass.

The real schema was verified via `npm pack`, not assumed:
`{schema:"squad-health/v1", status:"pass"|"fail", checks:[{id,status:"pass"|"fail"|"skip",message}]}`
with ids `team`, `registry-charters`, `routing`, `state-backend`, `env-vars`. **There is no `warn` status** —
the issue text was imprecise. Tests: `test_squad_health.sh` (56/0).

### #117 — externalized state / remote teamRoot
`stateLocation: "external"` or a non-`"."` `teamRoot` in `.squad/config.json` is refused by
`squad-aca doctor`, `squad-aca run`, and by the worker before the agent starts.

Semantics verified from `squad-cli`/sdk `dist/resolution.js`: `loadDirConfig()` treats the config as live
only when it has **both** a numeric `version` and a string `teamRoot`; `teamRoot: "."` is the sentinel for
"no remote root"; `stateLocation: "local"` is never written by Squad, so absence is the local signal.
Upstream `squad doctor` has zero awareness of these fields.

**Exit-code honesty:** the worker exits **78**, but the PowerShell surfaces `throw`, which exits **1**.
Doctor and run do *not* exit 78. A pre-existing docs entry claiming they did was corrected.
Tests: `test_external_state_refusal.sh` (36/0). Documented as a known limitation.

### Round 2 — REJECTED (`24b7143`): N1, N2, N3, S1-reopened, N5

- **N1 (root cause)** — the policy state lived in `$HOME/.squad-policy/`, owned by `squad`, the *same uid the
  agent runs as*, with no `--deny-tool shell(rm)`. A single `rm` undid F4, F6, F7 and F8 at once.
- **N2** — F4/F6 were 5-second sampler heuristics, not invariants, and their tests invoked the scanner
  manually, so they structurally could not catch the real attack.
- **N3** — the `.mcp.json` baseline-missing path.
- **S1 reopened** — the "symlinks are already handled" conclusion was an artefact of MSYS `ln -s` copying on
  Windows. On real Linux, `find <symlink-dir> -type f` returns zero files and detection is silently lost.
- **N5** — TERM/INT could interrupt the checkpoint and governance report.

### Round 3 — **APPROVED**

Fixes landed in `67a07b0` (lead) and `3ee4fa4` (lead), after engineer and reviewer were both locked out by
the reviewer-rejection protocol.

- **N1 closed with a real uid boundary.** `squad_root_seal_policy_state` runs as root in the few lines before
  the `runuser` drop. It creates a fresh root-owned `0711` directory under `/run` and starts a small root
  "sealer" process reading one pipe. Hardening hands the baseline to the sealer and reads the sealed copies
  back; a forged early seal makes harden exit 78. Sealed files are root-owned `0644` — readable by design,
  because the threat model is tampering, not secrecy. Verified as root in WSL: the dropped uid saw
  `DIR_STAT=0 711`, every file `0 644`, and **all ten** write attempts failed (rm, overwrite, append, mv,
  create, `rm -rf`, chmod, symlink-replace, report write, and even `ls`). The in-memory baseline and
  tripwires from `67a07b0` are kept as defence in depth.
- **N2 closed as far as is achievable** — see the residual below.
- **N3 closed** — the wrapper refuses (exit 78) when the `.mcp.json` baseline is missing, and the digest is
  now also checked against the sealed copy. (The earlier "the reason isn't in my notes" answer was wrong.)
- **S1 closed** — refused outright.
- **N5 closed** — TERM/INT are *recorded*, not acted on, through the checkpoint and the governance report,
  then honoured with `exit 0`. The sampler read retries when a trapped signal interrupts it, so a shutdown
  signal can no longer fake a violation.
- Sampler fd leak closed: every agent launch goes through `squad_policy_exec_agent`, which closes the sampler
  and seal descriptors before exec'ing the agent and refuses (78) if called in the hardening shell itself.
- The F7 governance report moved into the root-owned store and is written **before** `exit 78` on both the
  violation and tampered paths — the violation case is exactly when the report matters most.

Repros re-run and still blocked: A1, A2, A4, A5b, A5c, plus a forged early seal (which degrades to denial of
service, not bypass).

Suites added by the security work: `test_security_n1_state_tamper.sh` (35/0),
`test_security_n1b_root_sealed_state.sh` (50/0 as WSL root; skips loudly with 77 without root),
`test_security_n2_sampler_invariant.sh` (18/0), `test_security_n3_s1_symlink.sh` (11/0),
`test_security_n5_entrypoint_hardening.sh` (53/0).

### Accepted residual risks

1. **`chattr +a` is not used.** Nothing in the repo grants `CAP_LINUX_IMMUTABLE`, Docker's default capability
   set lacks it, and the `node:24-bookworm-slim` base image does not ship `chattr`. No speculative code was
   added. Consequence: a *partial* truncation above the baseline inside a single one-second sampler tick can
   go unseen. Closing this properly needs kernel append-only or inotify.
2. **Seal-pipe reachability.** A process at the agent's uid can reopen the seal pipe via `/proc`. Before the
   seal that is a denial of service; after it, it can only append noise to the report.
3. **PARITY is the watch/loop default** (Brian's explicit decision) — multi-word deny rules are not enforced
   on that path and are announced as such.
4. **`--allow-all-tools` in the resolved argv** is legitimate and required for non-interactive copilot.
5. **#115** — an inherited non-zero exit can skip the checkpoint in one narrow path.
6. **Sub-millisecond gap** inside `squad-signal-forwarding.sh`, and ACA's grace-period SIGKILL cannot be
   deferred.

### New finding from round 3 (non-blocking)

- **LOW — #117 log-forgery hardening gap.** The raw `teamRoot` value is echoed into diagnostics without
  sanitization, so a crafted config value could inject lines into the log. Non-blocking; left open.

### Performance

`test_governance_guard.sh` regressed to **159.9s** when the #113 governance classes landed — over the
120-second per-suite budget in `run-tests.sh`, which would have converted a known-failing suite into a *new*
suite-level failure. Root cause: in `squad_policy_write_manifest_file_lines`,
`lens["$rest"]="${line%% *}"` — `wc -c` right-pads counts when a shorter count shares output with a wider
one, and `%%` strips the *longest* `" *"` match, consuming the whole line and leaving an empty byte count.
Fixed in `1a496bb` with `read -r wc_len rest <<<"$line"`. The suite is now **~88s** (baseline 82.4s), a
−62% improvement over the regression and within budget.
